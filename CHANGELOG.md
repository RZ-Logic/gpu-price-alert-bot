# Changelog

## v2.1.0 (2026-10-21)

Fixes from a three-way review of v2.0.0. The retailers, commands and catalog models are the same. The database adds its new columns on first start; run `python -m pip install -r requirements.txt` again to pick up the certifi floor.

**Retailers.** A failure on a later page (block, timeout, HTTP or parse error, or an unexpected exception) keeps the earlier pages' listings and marks the result partial. Canada Computers, Newegg, Amazon.ca and Walmart report result rows they cannot read as `parse_error` instead of a healthy empty result, as Best Buy and Memory Express already did, so a layout change reaches the owner. Best Buy counts a SKU its stock API leaves unanswered as sold out, and fails the scan when no SKU gets an answer. A block followed by a timeout, 5xx or 404 on retry is still reported as a block, and bot-check pages are recognised at any size. Canada Computers no longer stops at a page without graphics cards. Walmart reads `sellerType` from a fixed list and falls back to the seller name.

**Matching.** 11 of the code review's 100 trick titles still pass `match()`, down from 17. Titles that list two models ("RTX 5070 Ti / RTX 5070") are rejected, "8/16GB" leaves VRAM unknown, and a stated memory size the model is not sold with is rejected (new catalog field `vram_options`). Damaged, as-is and untested listings are rejected, and more laptop titles are caught. Real cards are no longer rejected for a game-bundle promotion, feature text ("bracket included", NVLink, "M.2 NVMe SSD slot"), a possessive "'s", "V2", a glued "OC" or "FE", "RTX 508016GB" or "16GB DDR7". French accessory, bundle, condition and computer wording is recognised. In `/alert`, `/lookup` and the CLI, "RTX 5060 8GB" now asks which card is meant instead of picking the RTX 5060 Ti 8GB. The counts on all three labelled sets are unchanged.

**Alerts.** Every retailer that had an offer at or under target holds a disarmed alert until it answers completely; before, only the notified retailer did. A partial read counts for prices and pings but never re-arms an alert, and a holder that never answers completely lets go after 24 scans above target. A removed alert's reused id can no longer give a new alert another GPU's ping. If saving the state after a ping fails, the state is kept in memory and saved before the next decision, so the deal is not pinged every run. A `/check` reply that cannot be delivered puts its notifications back. An older background scan can no longer overwrite a newer `/check`. `/list` says "nothing eligible" instead of showing an old price next to a fresh check time. Three `alerts` columns (`holding_retailers`, `held_streak`, `observed_at`) and a `v1_imports` table are added on first start, and disarmed alerts are seeded so their notified retailer keeps holding them. `/health` no longer fails when it runs during the daily prune.

**Discord.** Commands answer only in `DISCORD_GUILD_ID`, the new `ALLOWED_GUILD_IDS` or, with neither set, servers the bot's owner is in, and in DMs to members of those servers; `/list` and `/remove` answer everyone. The invite link is logged before the command sync, a failed sync no longer stops startup, and the invite asks for Send Messages in Threads. Scans run on a pool of two threads and SQLite on a thread of its own, so commands answer within Discord's 3 seconds while scans run. The background scan order rotates every run. `/alert` warns about a target below the model's price floor, quotes only scans under 2 hours old, and makes a DM-only alert in a channel where the bot cannot post. An alert that reaches its user neither in its channel nor by DM gets one owner DM. The owner's "working again" DM waits for 2 good runs, and a DM that failed is sent again on the next run. Listing titles in embeds have Markdown, mentions and invisible control characters neutralised. Retailers turned off with `DISABLED_RETAILERS` no longer count as retailers that did not answer.

**Tooling.** `import-v1` run a second time changes nothing, and `--force` updates targets and channels. CLI `lookup` exits 1 when no retailer answered, and `--top` must be 1 or more. `.env` accepts `export `, and a warning names a key set twice (the first value is used) and any unknown `DISABLED_RETAILERS` id; a `CHECK_INTERVAL_MINUTES` below 1 falls back to 60. `requirements.txt` sets `certifi>=2026.10.19` (curl_cffi's CA bundle) for advisory GHSA-6q48-6c7w-9gw2. 798 offline tests (from 392) and 6 live ones. New among them: golden end-to-end runs of saved retailer pages through the production matcher and pricing (with v1's substring matcher swapped in, 14 tests fail), pinned request spacing (also for two threads at once), cooldowns and limits, and a guard that fails any offline test that tries to reach a retailer. `eval/evaluate.py` prints a one-sided 95% lower bound next to each precision and names the pre-registered queries a file does not cover. `tests/test_eval.py` pins the eval counts and the 11 adversarial accepts, and compares the pre-registered Targets table with the code.

**Review.** Three independent AI audits of v2.0.0, by Claude, Gemini and GPT, were cross-checked against each other. An issue was kept only when at least two agents confirmed it, one of them after trying to refute it, and arbiters settled severity disputes under one rubric. 54 distinct issues held up: 10 medium, 44 low, none high. All 10 medium issues and 37 low ones are fixed, with tests for the code and corrections for the docs. 6 low ones are fixed in part: four matcher issues (laptops and prebuilts, accessories and bundles, feature text, French wording; what is left is under Limitations), the Best Buy 100-row cap (now documented; the status line does not show it yet) and a retailer that keeps failing, which now holds an alert for at most 24 scans. 1 is kept as it is by choice: Canada Computers' "Available for Pre-order" and "Available to Order" labels still count as in stock (so far seen only on laptops, prebuilts and accessories). The open review items carried over from v2.0.0 are still open.

## v2.0.0 (2026-10-12)

A rewrite. v1's single file is replaced by the `gpu_alerts` package.

**Retailers.** Six: Best Buy (new, JSON search and stock APIs), Canada Computers, Memory Express (new), Newegg, Amazon.ca and Walmart. Newegg and Amazon.ca work again (they returned 403 and 503 to v1). Listings carry stock, seller, condition, regular price and shipping.

**Matching.** Titles are parsed into model, suffix and VRAM instead of matched by substrings. 33 catalog models, including VRAM variants. Pre-registered evaluation: precision and recall 1.000 on 397 held-out rows (309 distinct titles) and on 869 rows (325 distinct titles) from two retailers the matcher never saw, against 0.746 / 0.812 and 0.776 / 0.945 for v1. Caveats are in the README.

**Alerts.** SQLite instead of JSON files. One ping per crossing, further pings only on a 3% or $25 drop, re-arming after two scans above target in which the retailer that had the deal answered, restocks after a sell-out ping again. Price history is saved on every check.

**Discord.** Slash commands reply through deferred interactions, inputs are validated, `/lookup` and `/check` have cooldowns, `/prices` serves recent data, `/health` shows retailer status, and the owner gets a DM when a retailer keeps failing. No privileged intents. Optional instant command sync to one server.

**Tooling.** CLI (`lookup`, `health`, `import-v1`), 392 offline tests and 6 live ones, CI, MIT licence file, a working `.gitignore`, pinned requirements.

**Review.** Built from a live audit of v1 (four agents: retailers, code, platform facts, market) and a GitHub survey (two agents), which found no maintained Canadian GPU price-alert bot to fork. Three reviewers raised 27 findings after the build (2 high, 9 medium, 16 low); all high and medium findings are fixed with tests (the Canada Computers search depth was widened from 48 to 96 rows, not removed); 9 low ones are fixed, 2 in part, and 5 are left open and documented under Limitations.
